## Architecture

```text
Windows Electron controller
  |-- local USB ADB for first-time enrollment
  |-- SSH local forwarding for remote per-device ADB routes
  |-- embedded scrcpy decoding and input
  `-- Playwright/CDP browser controller
             |
             v
VPS relay
  |-- public mTLS phone ingress
  |-- mTLS status API with per-device bearer token
  |-- loopback-only enrollment API
  `-- one loopback ADB controller port per enrolled device
             |
             v
Android `All in` app
  |-- foreground service and partial wake lock
  |-- automatic outbound relay reconnection
  |-- local ADB probe and byte forwarding to 127.0.0.1:5555
  `-- boot receiver and persisted device identity
             |
             v
Android ADB -> Chrome DevTools socket -> Chrome tab DOM
```

The first USB setup is still required to authorize the desktop, install and provision `All in`, and enable `adb tcpip 5555`. A normal Android app cannot bootstrap ADB authorization itself.
